About Kypedia

Kypedia is a private reference library in encyclopedia form. It gathers long-form writing and research — essays, studies, notes, source lists — into one place where each piece can be linked, cited, and returned to. It makes no claim to cover a field systematically; it covers what its author has actually written about.

Purpose

Long pieces of writing tend to get lost. Kept as documents they are unlinkable; kept as blog posts they are ordered by date, which is rarely the order that matters. The encyclopedia form solves both problems at once: stable titles, stable section anchors, cross-references between entries, and sources attached to the claims they support.

The design follows Wikipedia's reading conventions deliberately. Readers already know how to use a lead paragraph, a table of contents, a footnote marker, and a category footer, and that familiarity is worth more than novelty.

Conventions

Lead first
Every entry opens with a paragraph that answers the question in its title, in plain language, without waiting for the argument to warm up.
Stable headings
Section anchors are permanent. Once an entry is published, a heading may be reworded only if its id stays the same, so that existing links keep landing in the right place. Hovering a heading reveals a ¶ control that copies its permalink.
Sources in place
Quotations are given in full where they are discussed, with the original language alongside a translation where that matters, and numbered footnotes collected under References. Uncertainty is stated rather than smoothed over.
One collection, many tags
An entry sits on exactly one shelf and reaches everything else through its tags. Tags come from a controlled vocabulary so the index stays usable as the library grows.
No dead ends
Each entry ends with See also, References, and a collection-and-tag footer, so there is always a way further in.

Collections

Collections are the shelves. They are broad on purpose — a shelf that needs splitting is a good sign, and splitting one is a small edit.

Tags

Tags are grouped into facets so that a few hundred of them remain readable. A tag answers one question about an entry: what it is about (subject), what body of material it works from (source), who it discusses at length (person), where (place), when (period), and how the work was done (method). Anything that does not answer one of those is probably a collection or a section heading instead.

The vocabulary is declared once in library.js; an entry may only use tags that already exist there. Below is everything currently defined, with counts for tags in use.

Status labels

Entries are published while still in motion, so each carries a maturity label in its metadata strip and in every listing.

Writing a new entry

Adding to the library is two edits and no build step.

  1. Copy templates/article-template.html to articles/<slug>.html, where the slug is lowercase, hyphenated, and permanent.
  2. Fill in the kypedia:* meta tags at the top of the file, then write the entry into the section scaffold.
  3. Append a matching record to KYPEDIA.entries in library.js. Nothing appears in any listing until this record exists.
  4. Open the browser console. The renderer validates the registry on every page load and reports missing fields, unknown collections, and tags outside the vocabulary.

Writing with an agent? Point it at AGENTS.md. That file is the normative specification: file layout, required metadata, the exact HTML skeleton, citation markup, tag rules, and the checks to run before finishing. This page is the human summary of it.

Files

index.html
Main page: collections, featured entry, recent updates, tag cloud.
browse.html
Full index. All filters are URL parameters (q, collection, tag, status, group, sort), so any view is linkable.
library.js
The registry: site details, collections, facets, tag vocabulary, status definitions, and one record per entry. The single source of truth for every listing.
render.js
Fills each data-kp-render slot from the registry and validates it. Pages declare what they want; the renderer decides what goes there.
styles.css · kypedia.css
Reading layout, then the Kypedia brand layer on top of it.
script.js
Per-page behaviour: table of contents, scroll tracking, find on page, heading permalinks, print.
articles/ · templates/
One file per entry, and the skeleton they start from.

Kypedia — static HTML, no dependencies, no build step. It runs from a local file or any static host.
